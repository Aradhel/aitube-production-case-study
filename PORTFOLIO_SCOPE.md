# Public Portfolio Scope

## Safe to publish

- Product problem and target workflows
- Publicly visible feature descriptions
- High-level architecture and job lifecycle
- Original, approved screenshots of the public landing page and creator UI
- Original demo videos made with owned or authorized assets
- General engineering decisions and lessons learned
- Links and attribution for upstream open-source projects
- Responsible-use, privacy, and security principles

## Keep private

- Production source code and proprietary orchestration details
- Environment files, API keys, tokens, passwords, and webhook secrets
- Account, billing, email, GPU, storage, and deployment configuration
- SQLite files, database dumps, migrations containing real data, and backups
- Logs, analytics exports, job identifiers, IP addresses, and server paths
- Customer images, audio, scripts, generated videos, and file hashes
- Model weights and third-party sample assets
- Internal abuse rules that would make safeguards easier to evade

## Media checklist

Before committing a screenshot or demo:

1. Confirm every face, voice, logo, and background is owned, generated for the project, licensed, or explicitly authorized.
2. Remove email addresses, account IDs, billing information, job IDs, browser bookmarks, and notifications.
3. Crop out local paths, IP addresses, terminals, logs, and provider dashboards.
4. Verify the media contains no embedded secrets or private metadata.
5. Use English UI and captions for the public portfolio.
6. Add an AI-generated-media disclosure when appropriate.
